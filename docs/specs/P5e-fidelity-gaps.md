# P5e fidelity gaps: Automation center, chosen mockup vs live

Author: Ophelia (Opus, analysis subagent) · Date: 2026-11-07 · Parent spec: `P5e-automation-center-redesign.md` · Status: **ready to dispatch**

The owner says the live Automation center "doesn't look at all like the previews" they chose (variant A plus two pieces of C). This file lists every gap between the mockup and production, ordered by visual impact, with a concrete fix for each. Implementers won't see the mockups (they are gitignored), so each section describes the target layout, copy and colours in full.

## How this was measured

- **Mockup:** `.private/design/automation-center/variant-a.html` (and the "from C" parts of `variant-c.html`), served locally and opened in Chrome, dark and light, "With automations" and "Empty" boards. Values below come from `src/core.css` and `src/app.js` (the mock's source) and computed styles in the browser.
- **Live:** https://atrium-workboards.web.app, showcase board, "Automate" button, dark theme, read-only (nothing toggled, created, run or saved). Computed styles were read with JavaScript. Code at `origin/main` `ec6caf2` (R1 to R4, the P5c follow-up and P5d-4 are all merged).
- Mockup px values are listed so they can become **tokens** in `apps/web/src/theme/automation-tokens.css` (the only place literals are allowed; see the token table at the end). Components use tokens only (AGENTS.md "Visual identity").

## 1. Shell and header (biggest single gap)
