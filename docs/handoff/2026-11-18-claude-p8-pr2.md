# 2026-11-18 Claude: P8 PR 2, Settings "API tokens" card

Branch `claude/p8-tokens-ui` (from `origin/main`, which has PR 1: the `createApiToken` and `revokeApiToken` callables, the shared schemas and the self-read rule).

## What was done

- `apps/web/src/pages/settings/ApiTokensCard.tsx`, rendered in the Account tab after Connected apps. Live list of `users/{uid}/apiTokens` (newest first), name, stored prefix with an ellipsis, access, workspace restriction (names when known), created, last used, expires. Revoke asks first (`ConfirmDialog`) and calls `apiTokenCalls.revoke`.
- `ApiTokenCreateDialog.tsx`: name (required, 60), access (Read only default, Read and write), workspaces (all, or pick from the ones you belong to), expiry (30 days, 90 days default, 1 year). On success the token is shown once in a read-only box with Copy and Done. It lives only in the dialog's state: not in localStorage, logs or the URL; closing discards it.
- `api-tokens.ts` (model and form validation), `data/api-tokens.ts` (`useApiTokens`), `refs.apiTokens` and `queries.liveApiTokens` in `data/firestore.ts`, `ApiTokenDoc` in `data/model.ts`.
- Privacy notice: one bullet under "What Atrium stores" (token stored only as a hash; name, prefix, access, workspaces, dates and last-used time kept until revoked or expired). The date line moved to 18 November 2026. API call and webhook delivery logging is not claimed yet; add that sentence with the API routes.

## Decisions

- Revoked tokens are hidden (the query filters `revokedAt == null`, like Connected apps). Expired tokens stay in the list, dimmed and labeled "(Expired)", so the person can revoke or recreate them.
- Vibe `TextField` sets `role=""` on its input, so tests find it with `getByLabelText`.
- The expiry control is a native `select` (same as the time-zone select in Settings), since Vibe's Dropdown is heavy for three options.
