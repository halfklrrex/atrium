# 2026-11-18: Claude, P8 PR 7b (Integrations dialog for webhooks)

Branch `claude/p8-hooks-ui`, based on `claude/p8-incoming` (PR 7a). Web only: no backend or rules changes.

## What was done

- **Entry:** board menu item "Integrations", shown to board owners only (`canManageBoard`). It opens the
  `integrations` dialog through the UI store (`DialogHost`). The entry stays visible when the feature flag is off.
- **Dialog** (`apps/web/src/components/integrations/`): two sections.
  - Outgoing webhooks: live list (name, host only, events summary, status, failures, last delivery), Add, Edit,
    enable switch, Test (queues a ping, toast), Deliveries, Rotate secret (confirm), Delete (confirm).
  - Incoming webhooks: live list (name, short id suffix, enabled, last used, default group), Add, Edit, enable switch,
    Rotate URL (confirm), Delete (confirm), and a curl example with a placeholder URL.
- **Secrets shown once:** `SecretRevealDialog` holds the signing secret or the incoming URL in component state only.
  Closing it discards the value. Nothing is stored, logged or put in the address.
- **Limits:** Add is disabled at 5 outgoing and 5 incoming, with a hint.
- **Feature off:** a failed-precondition whose message contains "not switched on" shows
  "Webhooks aren't switched on yet." in the dialog. Other errors show the server's message through
  `describeCallableError`. Detection is by message text (`isWebhooksOff`), because the backend uses one code for several refusals.
- **Data layer:** `useBoardWebhooks`, `useBoardIncomingHooks` (`apps/web/src/data/integrations.ts`), refs and converters in `firestore.ts`.
- **Tokens:** four `--atrium-integrations-*` tokens in `theme/settings-tokens.css`.
- **Tests:** model helpers, dialog flows with mocked callables (create-once secret, limits, flag off, test/rotate/delete confirms,
  deliveries states), and the owner-only menu entry. Visual screen `board: Integrations dialog` with Admin SDK seeds in `tests/visual/src/seed.ts`.
