## Gotchas

- **`pnpm licenses list --prod` is a superset of what is bundled.** `@vibe/shared` (a dependency of `@vibe/core`) lists `vitest` as a real dependency, so vitest, jsdom, vite and friends show up in the web production closure. We keep them in the notices on purpose (conservative, and the spec says to use pnpm's list). Every licence in that closure is permissive.
- **Platform-specific native packages are skipped** (`@esbuild/win32-x64`, `@rolldown/binding-*`, `lightningcss-*`): they declare `os`/`cpu`, differ between Windows and the Linux CI runner, and would make the generated file differ per OS. They are build tooling and carry their parent's licence.
- **The generated file contains no paths or dates** and uses plain string sorting, so it is identical on Windows and Linux. If `licenses:check` fails in CI after a dependency change, run `pnpm licenses:notices` and commit the result.
- **Unknown licences fail the check.** To accept a package whose licence metadata is missing or odd, read its licence file and add an entry to `REVIEWED_OVERRIDES` in the script with a reason. Currently empty.
- **`LICENSE` and `THIRD_PARTY_NOTICES.md` are in `.prettierignore`** (verbatim or generated text).
- **The version is `dev` when built without git** and falls back to `GITHUB_SHA`; the links then point at `main`.
- The login footnote gains a "Source code" link, but the change stays inside the visual tests' `maxDiffPixelRatio` (0.002), so the `visual` CI job passes with the existing baselines. The "Update visual baselines" workflow was run on the branch and committed nothing. The About dialog and avatar menu are not covered by a screenshot test.
