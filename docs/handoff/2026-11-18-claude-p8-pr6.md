# P8 PR 6: outgoing webhooks (backend only)

Branch `claude/p8-webhooks`. Implements PR 6 of `docs/specs/P8-public-api-and-webhooks.md` (sections 2 D6 to D9, 5.1, 6, 8, 9, 10): data, rules, callables, the SSRF guard, the producer in `onActivityCreated` and the `deliverWebhooks` sweep. No UI (PR 7), no incoming hooks, nothing in `functions/src/api/`.

## What changed

- `packages/shared/src/webhooks.ts`: limits (name 60, url 2048 https only, `WEBHOOK_MAX_PER_BOARD = 5`, 5 attempts, retry delays 1 min / 5 min / 30 min / 3 h, 20 failures to switch off, 14 days retention, 64 KB payload, 500 response characters), callable names, request and result schemas, the webhook, delivery and payload schemas. Events are activity kinds or `["*"]` on its own.
- `firestore.rules`: `boards/{id}/webhooks/{id}` is read by board owners only (`canManageBoard`), no client write. `webhookSecrets` and the top-level `webhookDeliveries` have no rule (default deny); there is no collection-group rule either. Tests: `tests/rules/src/webhooks.test.ts`.
- `firestore.indexes.json`: composite index `webhookDeliveries (status, nextAttemptAt)` for the sweep.
- `functions/src/webhooks/`:
  - `ssrf.ts`: static URL rules (https, port 443, no credentials, no IP literal in any spelling, no `localhost`, `*.localhost`, `*.internal`, `*.local`, single-label hosts and a few more suffixes), address classification (IPv4 reserved ranges; IPv6 only global unicast, with mapped, NAT64 and 6to4 forms judged by the embedded IPv4), `resolvePublicAddress` (every returned address must be public), `prepareDelivery` (both), and the transport (`createHttpsTransport`: connects to the resolved address with `servername` and the `Host` header set to the original name, `agent: false`, no redirects, 5 s deadline, 500 characters of response). The transport and the resolver are injectable.
  - `signature.ts` (secret `whsec_` + 32 bytes base64url; `Atrium-Signature: v1=<hex HMAC-SHA256 of "<timestamp>.<body>">`), `payload.ts`, `manage.ts` (the five callables as plain functions), `enqueue.ts` (producer), `deliver.ts` (sweep), `notify.ts`, `store.ts` (seam), `admin-store.ts` (Firestore), `fake-store.ts` and `testkit.ts` (tests), `flag.ts`.
- Callables `createWebhook`, `updateWebhook`, `deleteWebhook`, `rotateWebhookSecret`, `testWebhook` (all through `actorFromRequest`), scheduled function `deliverWebhooks` (`* * * * *`, 120 s), exports in `functions/src/index.ts`. Web wrappers `webhookCalls` in `apps/web/src/lib/callables.ts`.
- `onActivityCreated` calls `enqueueWebhooks` first, in its own try/catch (logs board id, activity id and an error code, never the payload); the automation code and its tests are untouched.
- Notification kind `webhook_disabled` (shared enum, `notifications.ts`, `push.ts`, bell card text, icon, click opens the board). No pref switch and no push (fail closed). `recipeName` carries the webhook name, `itemId` the webhook id.
- `WEBHOOKS_ENABLED=false` in `functions/.env.atrium-board` and in the allow-list of `scripts/functions-env.test.mjs`.

## Behavior to know

- **Kill switch.** Off (anything but `true`): callables answer `failed-precondition`, the producer reads and writes nothing, the sweep returns at once.
- **Secret.** Returned by `createWebhook` and `rotateWebhookSecret` only; stored in `boards/{id}/webhookSecrets/{webhookId}`; the webhook document never holds it. Rotation applies to deliveries still queued (the sweep reads the current secret).
- **Queue.** Delivery id `${webhookId}_${activityId}` with create-if-absent. `payload` is the JSON text (signed exactly as stored). `expiresAt` is a Timestamp (TTL). Pings use `${webhookId}_ping_<id>`.
- **Claim.** A transaction re-reads the delivery and, when it is still `pending` and due, moves `nextAttemptAt` forward by a 3 minute lease (a sweep sends at most 50, 10 at a time). A crashed sweep's deliveries come back after the lease.
- **Outcomes.** 2xx is `sent`. 408, 429, 5xx, network errors, timeouts and DNS failures retry (1 min, 5 min, 30 min, 3 h; the fifth failed attempt is `dead`). Other 4xx and any 3xx are `failed` without a retry (redirects are never followed). A host that now resolves to a private address, or a stored URL that breaks the rules, is `failed` without sending. A deleted, disabled or secretless webhook ends its pending deliveries as `dead` without sending. Every failed attempt counts toward `consecutiveFailures`; a success resets it; the 20th switches the webhook off (`enabled: false`, `disabledReason`) and notifies `createdBy`.
- **Save-time guard.** Create and update (when the URL changes) run the static rules and a DNS lookup and answer `invalid-argument` with a readable reason.
- **Test button.** Only for an enabled webhook; queues a `ping` the next sweep sends.
- **Payload.** Spec 5.1; `data.from` and `data.to` are the raw stored values (the activity's `fromValue` and `toValue`, else the display texts), plus a few small pass-through fields (`snippet`, role and kind changes). Strings are clipped to 200 characters, an actor name that looks like an email address becomes "A member", and a body over 64 KB is replaced by `data: {truncated: true}`.

## Not done / open

- **Privacy notice.** `apps/web/src/pages/privacy/privacy-content.ts` is not changed here (the API PR also edits the privacy text for tokens and the audit log, so one PR should add the sentences together). Text to add: webhook deliveries (event id, item id, item name, actor name and the changed values, never email addresses) are queued by id for 14 days and then deleted, and are sent to the address the board owner chose.
- The real HTTPS transport is tested with an injected `request` function (options, pinning, 500 characters, timeout, redirects), not against a live TLS server.
- `onActivityCreated` itself has no unit test for the producer call (the repo has none for the trigger body); `enqueueWebhooks` is covered by unit tests and the emulator e2e, which hands the activity entry to it as the trigger does.
- Delivery history is not exposed to clients (a UI delivery log in PR 7 needs a callable or a rule change; the queue is Functions-only by design).
- Delivery order is not guaranteed (the sweep is oldest first, retries come later).
