# P8 PR 3: the `api` function, read routes

Branch `claude/p8-api`. Implements PR 3 of `docs/specs/P8-public-api-and-webhooks.md` for the read routes only. Write routes are PR 4; OpenAPI and the docs page are PR 5; no webhooks.

## What changed

- `functions/src/api/app.ts`, `index.ts`: the Express app and `export const api = onRequest({ invoker: 'public', cors: false, timeoutSeconds: 55, memory: '512MiB', maxInstances: 3, minInstances: 0 })`, re-exported from `functions/src/index.ts`. Pipeline per request: `Cache-Control: no-store`, kill switch (`API_ENABLED !== 'true'` gives `503 api_disabled`, nothing else runs), JSON body parser (256 KB), per-IP failure window, `verifyApiToken` (one deps object per instance; `verifyOAuthToken` is `AtriumOAuthProvider.verifyAccessToken`), scope, per-token minute window, daily counters, route. `trust proxy` is 2, like `mcp`.
- `functions/src/api/errors.ts`: `{ error: { code, message } }`. `McpUserError` is mapped by wording (`was not found` and `, not active.` give 404, role messages give 403, anything else 400); zod issues and body-parser errors are 400 (413 for a too-large body); anything else is a generic 500 `internal` and only the error object is logged.
- `functions/src/api/limits.ts` (all constants in one file): 120 calls a minute per token (or per user for OAuth tokens), 5,000 calls and 1,000 writes a day in `apiUsage/{tokenId or uid}` (with `expiresAt`, three days, pushed out on use), 300 failed authentications an hour per IP. All answer 429 with `Retry-After` (60, seconds to the next UTC midnight, 3600).
- `functions/src/api/audit.ts`: `system/apiAudit/entries/{id}` with `kind` (`call` or `auth_failed`), method, route pattern, board id, ok, status, error code, ms, uid, tokenId, `expiresAt` = 90 days. No body, query string, header, token or email. Written before the response is sent (best effort).
- Routes in `functions/src/api/routes/` (`account.ts`, `boards.ts`, `items.ts`, `paging.ts`): `GET /api/v1/me`, `/workspaces`, `/workspaces/:id/boards`, `/boards/:id`, `/boards/:id/items`, `/boards/:id/members`, `/items/:id`, `/items/:id/updates`. Each calls `createService({ client: createAdminClient(db()), actor: { uid, workspaceFilter: token.workspaceIds } })`, so the service is the only gate.
- `functions/src/mcp/limits.ts`: `MinuteLimiter` got an optional window (default one minute, so MCP is unchanged) and `over(key)`; `adminUsageStore` got an options argument (`collection`, `ttlMs`).
- `firebase.json`: rewrite `/api/**` to function `api` before the catch-all, and `Cache-Control: no-store` for `/api/**`. `scripts/api-hosting.test.mjs` guards both and that the web app has no route or public folder under `/api`.
- `functions/.env.atrium-board`: `API_ENABLED=false`; `scripts/functions-env.test.mjs` allows it and checks it is true or false.

## Changes to `@atrium/mcp-core` (MCP behavior unchanged)

- `createService`: `actor.workspaceFilter` may now be a list of workspace ids (a PAT can be restricted to several). A single id behaves exactly as before; an empty list shows no workspace at all (never "no restriction"). Types updated.
- New service methods `locateItem({ itemId, boardId? })` and `getItem({ itemId, boardId? })` (the API's `/items/:id` has no board id). Without the hint it looks only at boards the actor can read (one `get` per readable board, ten at a time); an item elsewhere, archived or missing is the same "was not found" error. `getItem` returns `values` keyed by column id, `valuesByTitle`, the group, and nested `subitems`. Neither is a tool.
- `findItems` and the fake client got type declarations (`index.d.mts`, `fake-client.d.mts`, package export with types). Tests: `packages/mcp-core/src/item-lookup.test.mjs`.

## Behavior to know

- Response shapes reuse the MCP output builders: items in a page are `{ id, seq, name, group (title), values keyed by column title }`; `/items/:id` is the richer shape above. Paging is `?limit=` (default 50, silently cut to 200, 0 or non-numbers are 400) and `?cursor=`, an opaque base64url `{v:1,o:offset}`; the page reads the board's items again each time (fine at this size). Response: `{ boardId, total, limit, items, nextCursor|null }`.
- `GET /boards/:id` is `getBoard` without items (columns, groups, labels, access). `/boards/:id/members` drops email addresses (ids and display names only, per the spec's privacy rule). `/workspaces/:id/boards` takes `?state=active|archived`.
- `?board=<id>` on `/items/:id` and `/items/:id/updates` is an optional hint that skips the board search.
- A token without `read` is 403 `forbidden`; for non-GET methods (PR 4) the guard answers 403 `read_only` when `write` is missing and counts the call as a write.
- The auth result is kept in `res.locals.auth`, not `req.auth`, because the MCP SDK types already own `req.auth` with a different shape.
- Unauthenticated requests to any path under `/api/v1` (even unknown ones) get 401 first; an authenticated unknown path is 404.

## Ultrareview fixes (second round)

- `createService({ hideEmails: true })` (used only by the API): names are the display name or "A member", never an email; email fields are omitted (members, updates authors whose stored name is an email).
- The per-IP failure window is best effort and runs only after a token failed verification; a valid token is never blocked (a direct run.app call can spoof X-Forwarded-For).
- OAuth verification: only the provider's `InvalidTokenError` is an auth failure; other errors propagate as a 500 and are not counted.
- `findItems({ uniqueTitles: true })` (API list only) keys later same-title columns as `Title (columnId)`; `getItem` uses the same helper.
- Early 413 for a body over 256 KB (Content-Length or a pre-parsed `rawBody`).
- Rate-limit rejections are audited at most once per key per minute; a reached daily cap is cached in memory until the next UTC day.
- `getItem` reuses the board and item that `locateItem` already loaded. The board scan without `?board=` is a known cost (see `docs/DEPLOY.md`).
- Rules tests deny clients on `apiUsage` and `system/apiAudit/entries` (`tests/rules/src/api-functions-only.test.ts`).
