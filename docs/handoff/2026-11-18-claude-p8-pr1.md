# P8 PR 1: personal access tokens (data, rules, callables, verifier)

Branch `claude/p8-tokens`. Implements PR 1 of `docs/specs/P8-public-api-and-webhooks.md` (sections 2, 3, 6, 8, 9). No HTTP route, no web UI and no webhooks yet.

## What changed

- `packages/shared/src/api-tokens.ts`: zod schemas and types (scopes `read` / `write`, name up to 60, `expiresInDays` 30, 90 or 365, optional `workspaceIds`, create and revoke request and result, the `users/{uid}/apiTokens/{tokenId}` document), callable name constants, `API_TOKEN_MAX_ACTIVE = 10`.
- `firestore.rules`: `users/{uid}/apiTokens/{tokenId}` self-read for approved owners, no client write; `apiTokenIndex` has no rule (default deny). Tests: `tests/rules/src/api-tokens.test.ts`.
- `functions/src/api/`: `tokens.ts` (create, revoke, revoke all), `token-store.ts` (storage seam), `admin-token-store.ts` (Firestore adapter), `fake-token-store.ts` (tests), `auth.ts` (verifier).
- Callables `createApiToken` and `revokeApiToken` (approved accounts only through `actorFromRequest`, exported from `functions/src/index.ts`); web wrappers `apiTokenCalls` in `apps/web/src/lib/callables.ts`.
- `setAccountStatus` block also revokes the account's API tokens, best effort, like the MCP grants.

## Behavior to know

- Token is `atrp_` + 32 random bytes base64url. Only the SHA-256 hex goes into `apiTokenIndex/{hash}` (`uid`, `tokenId`, `expiresAt` Timestamp). The token document keeps the first 8 characters as `prefix`. The token is returned once by `createApiToken`.
- The 10-active-token limit is checked in the same Firestore transaction that writes the documents. Revoked and expired tokens do not count. A repeat revoke is a no-op (`revoked: false`).
- Revoke finds the index document by querying `apiTokenIndex` on `uid` and `tokenId` (two equality filters, no composite index), so the hash is never stored on the readable token document.
- Workspace restriction: the caller must be in `workspaces/{id}.roles` for every id; duplicates are removed and an empty list means no restriction.
- `verifyApiToken(header, deps)` / `ApiTokenVerifier.verify`: Bearer parsing, `atrp_` goes to the hash lookup, anything else goes to `AtriumOAuthProvider.verifyAccessToken` (injected as `verifyOAuthToken`). Account status uses the existing OPS4 `AccountStatusCache` (60 s, 500 entries). A verified PAT is cached 60 s per instance (500 entries, oldest first out); failures are never cached; a cached token is still refused after its own `expiresAt`. `lastUsedAt` is written at most once a minute (per instance and across instances, from the document), best effort.
- OAuth tokens are bound to the `/mcp` resource by OPS4, so they are accepted by the API verifier as they are; their scopes map `atrium:read` to `read` and `atrium:write` to `write`, with no workspace restriction.
- Every verifier failure is a 401 (`ApiAuthError.reason` is for the audit log only; the message is generic).
